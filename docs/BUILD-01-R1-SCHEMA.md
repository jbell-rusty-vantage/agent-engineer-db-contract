## A. Model and physical choices

An authored **work** has stable identity and immutable saved **revisions**. A course, track, module, lesson, activity, report, dataset snapshot, decision definition and action policy use this one revision mechanism. A curriculum **part** is a stable occurrence of an exact child revision inside a parent revision; reuse does not imply ownership or copying. Outcomes and requirements attach to exact revisions. A private **release** freezes a root and its transitive dependencies; an **enrollment/adoption** records what a person chose to study. It does not establish a grade, mastery, official publication or access to otherwise private sources.

Keep `orchestration.artifact`, its pending/available/failed lifecycle and byte custody; `evidence.source`, `source_capture`, `locator`, `claim`; `corpus.entity`; `knowledge.record`; tenant-local `temporal.knowledge_batch`; KS verification/report-v2 and MC contracts. Reuse their IDs through explicit bindings, never copy their truth into a second artifact/evidence/mission registry.

Merge the historical proposals `work_block` and small representations into the validated revision body; assets/dependencies/evidence into a typed binding table; proposal/review/change-notice history into a typed event table. Do not create separate `curriculum.unit`/`unit_version` identities over the same authored work. Keep release, composition and adoption relational because they need integrity, reverse queries and independent lifecycle. No vector space, general dataset editor, universal decision engine or separate scheduler is introduced.

## B. Exact relation dictionary

Notation: `uuid`, `text`, `integer`, `bigint`, `boolean`, `jsonb`, `timestamptz` are PostgreSQL types. `?` means nullable; otherwise NOT NULL. Every `id` defaults to `util.uuidv7()` unless explicitly supplied for conversion; every `created_at` defaults to `now()`. Text discriminator sets below are CHECK constraints, not PostgreSQL enums. Digests are lowercase 64-character SHA-256 hex with a regex CHECK. Required names/statements/reasons are nonempty after trimming. JSON is shape/version validated by the write function and the shared client schema; all writes enter that function. Unknown is explicit, never an empty success value.

All new tables except workspace membership carry `tenant_id uuid, workspace_id uuid`; their pair references `authoring.workspace(tenant_id,id)` with ON DELETE RESTRICT. Each ID table has PK `(id)` and UNIQUE `(tenant_id,workspace_id,id)`. All intra-workspace references use composite FKs; a globally valid UUID from another workspace cannot satisfy them. Workspace membership has the same scope pair as its FK and composite PK below. No new tenant column defaults to the single-tenant helper. Actor columns reference `auth.users(id)` with RESTRICT; a future removal policy must explicitly handle retained audit identities.

The seventeen relations above are the complete new product table set for R1. `learning` contains no submission, grade or mastery tables. `authoring.command` is local product write idempotency, not an MC operation-journal replacement. `authoring.event` is a typed audit/feedback history, not an arbitrary graph. `asset_scope` supplies the access boundary missing from the tenant artifact registry, including the pre-attachment upload state.

### JSON contracts, validation and hashes

`aieng.work-body.v1` has `{formatVersion:1, blocks:[{id,kind,content}], metadata:{...}}`. Block IDs are UUIDs unique within a revision; kinds markdown/code/image/file/interaction. Code content names language, text and optional file binding key. Image/file content names a binding key and accessible caption. Interaction content names a trusted renderer ID/version plus validated data and binding keys; no arbitrary script execution in the main origin. Metadata is a discriminated union selected by work kind. Unknown fields are rejected outside a named `extensions` object capped at 16 KiB. Canonical hashing uses sorted JSON object keys, preserves array order and UTF-8; persist the algorithm version. Work content digest covers the body/title and sorted binding/composition/outcome/requirement/prerequisite records; it excludes timestamps and mutable current head. Seal a full revision atomically only after all children are inserted and validated. Triggers prohibit later child inserts as well as updates/deletes once that revision command commits. Revisions can be constructed only inside the write function; the seal is represented by a nonnull content digest set at the end of that transaction, with a deferred constraint forbidding unsealed committed revisions.

Metadata contracts: course/module/lesson/activity carry brief, audience, prerequisite guidance, intended duration (estimate, not completion evidence), author role and activity instructions. Dataset is a **bounded immutable snapshot**, maximum 100 rows and 20 fields, stable row/field UUIDs, explicit value origin observed/inferred/calculated/unknown/conflicting, and cell→binding keys. Report references exact dataset revision/bindings. These do not implement the arbitrary editable RV08 dataset service.

Decision definition metadata preserves input schema, question IDs, choice/predicate/score answer schema, stable options/ordered rubric, insufficient-evidence behavior and preparation version. Action-policy metadata preserves deterministic branches, applicability, thresholds and error-cost rationale. Decision-attempt metadata references definition/policy/input through binding keys and records execution kind rules/manual/provider/fixture, provider/model/adapter requested and returned when real, input digest, answer status answered/insufficient_evidence/refused/timeout/invalid_result/error, typed value and native distribution/confidence semantics, usage/cost/latency or explicit unknown, attempt/retry identity. Human correction and actual application are separate events, referencing answer IDs and old/new target revisions. Fixtures cannot identify themselves as model runs. Policy replay creates a new application event, not a new model answer. This preserves the approved bounded-decision distinctions without copying KS Jev's engine into course SQL.

R1 application events use the `reviewed` event payload union with `reviewType=decision_application|human_correction|release_review|content_review`. A release review must be human and bind exact root/closure digest, audience=private_preview and decision=approve. An automatic decision application can only propose a revision; it cannot authorize sharing, publication, membership or adoption. Revisions are frozen independently of a later policy application.

Binding target matrix: representation→artifact; source→capture or locator; supports/contradicts→claim or locator or knowledge record; covers/targets→entity or knowledge record; derived_from_problem→knowledge record; derived_from→revision; uses→revision or artifact. A capture/locator's artifact must have active same-workspace asset_scope, unless the explicitly permitted reference-only source rule applies; a citation never grants its bytes. Preserve referenced capture/claim revision semantics as defined in their current contracts. Save copies the complete revised content/edge set with new row IDs and stable block/occurrence/outcome/requirement keys; it never appends new edges to an already saved revision.

Review authority derives from the authenticated interactive confirmation, not an agent-supplied `actor_kind=human`. Native harness agents may propose review requests; John's explicit confirmation through web or interactive CLI records the human release review with exact digest. This is a content review, distinct from John's R1 schema approval. Fixture human actors remain labeled fixtures and are not John's feedback.

### Access and artifact invariants

Enable and FORCE RLS on all seventeen tables. Revoke all table/function access from PUBLIC/anon and existing broad service roles by default for the new schemas; grant only the new API functions to authenticated. Use a dedicated NOLOGIN `course_api_owner` with explicit necessary grants, no BYPASSRLS and no inherited executor role. `api.course_command` and `api.course_read` are SECURITY DEFINER with empty search_path, qualified identifiers and strict operation allowlists. Inside each function, obtain the verified `auth.uid()` and resolve current workspace membership; caller-supplied tenant/actor fields are rejected. The API-owned workspace-access helper uses a narrowly privileged owner to read membership without recursive RLS, checks auth.uid(), and returns only boolean access to the requested workspace. Helper EXECUTE is unavailable directly to clients. No global tenant-default fallback authorizes a product user. Set transaction-local app.tenant_id only after membership resolution for scoped existing-contract calls, never directly from request input. Learning row reads additionally require learner_id=auth.uid(); workspace editor status alone does not reveal learner adoption/personal state.

Workspace bootstrap creates only a private space for auth.uid(); tenant comes from trusted server enrollment/configuration, never request JSON. In this local single-tenant cycle use the existing tenant UUID `00000000-0000-7000-8000-000000000001`. Test an additional tenant via privileged test setup solely for negative cases. New scope does not silently rewrite common util helpers or expose legacy service APIs to users.

Readers can read permitted content; editors/owners can revise/review private content; only owners can change membership; only learners adopt. Binding to an old source/artifact requires explicit admissible access, not just a same-tenant UUID. R1 permits newly registered artifacts in the same workspace or an explicitly allowlisted public reference-only source. No blanket import of historical tenant-private assets. Cross-workspace reuse/sharing is rejected; future selective promotion must make separate grants/copies explicit. Historical reads recheck current membership, source rights and withdrawal. Revocation denies subsequent metadata, lookup, export and byte requests.

Add one private general-product bucket `aieng-workspaces`, not one per feature, using existing `orchestration.artifact` IDs. This isolates new user-scoped files from the inspected operator-oriented buckets/policies. Objects use `<tenant>/<workspace>/<artifact-id>/<sha256>`; no overwrite or cross-workspace byte aliasing. Existing verification-v1 CAS constraints remain unchanged: these artifacts use the existing general artifact path with verification_contract_version NULL and must not pretend to be KS verification artifacts. Add artifact type codes `authored_work_asset`, `course_release_manifest`, `course_source_capture` through the existing artifact-type lookup, using its actual required columns.

The server atomically registers pending identity plus asset_scope, streams upload, verifies digest/length/type, then marks available using existing lifecycle. Attachment/release rejects pending/failed/missing objects. Retry uses original artifact ID and immutable bytes; existing successful object is compared, never overwritten. No user gets a service key. Download through the authenticated product endpoint checks asset_scope, binding, workspace, current source rights and object digest; don't issue durable bearer download URLs. Storage denies anon/authenticated direct access to this bucket, including listing. Verify existing permissive policies cannot match it. Small bodies remain JSON; actual files, input captures, source/build bundles and manifests are objects. complete_asset/fail_asset are internal worker operations with verified storage readback, never trusted client assertions that an upload completed. Expose only upload initiation/status through client adapters; hash verification and finalization run server-side.

Index every new FK on its referencing columns; unique constraints already covering the prefix suffice. Add reverse indexes on binding target columns (partial WHERE nonnull), part child_revision_id, event(work_id,created_at), release(course_work_id,release_no), adoption(enrollment_id,sequence_no DESC), and membership(principal_id,workspace_id) WHERE revoked_at IS NULL. No embeddings or broad GIN index until a demonstrated query requires them.
