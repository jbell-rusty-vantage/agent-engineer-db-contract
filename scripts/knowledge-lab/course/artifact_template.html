LESSON 0

From text that describes an action to a model that takes one

In 2022 a language model could only write text. To make it do something, you asked it to write the action down in a format your program could parse, then you ran the action and pasted the result back. The ReAct paper (Yao et al., October 2022) named the pattern: interleave Reasoning and Acting. LangChain shipped a month before ChatGPT and made that loop a library, and that is the door this module walks through: an agent is a loop in which a model chooses a function and its arguments, your code executes it, and the result goes back to the model.

THE LIBRARIES THROUGH TIME

Four years of releases, from captured PyPI data

Each band is a package; bar height is the number of releases published that quarter; the labels mark the first release of each minor line. KB · registry PyPI JSON captured 2026-11-13.

What the shape saysLangChain's 0.0.x era was one release every few days (the library was the field's sketchbook). The 0.1 cut in January 2024 is the turn toward stability; langchain-core had been split out two months earlier so integrations could depend on a small, stable kernel. LangGraph arrives in January 2024 and its 1.0 lands the same day as LangChain's (2025-10-17 on PyPI). Deep Agents ships fastest of all: 150 releases in fifteen months.
For your projectsA tutorial is pinned to a date. Lesson 2 shows what changed between a 2025 tutorial and today's packages; our probes re-run those checks whenever a subject library ships (deepagents 0.7.38 shipped while this module was being built and two probes were re-run).

The docs' philosophy page states two focuses: let developers build with the best models without lock-in (one message format across providers), and let models orchestrate flows that touch data and computation, not only generate text.

Below everything is one idea from langchain-core: a Runnable has invoke, stream, batch and async twins. Chat models, tools, compiled graphs and the Agent Server's RemoteGraph all speak it, which is why a deployed agent can be dropped into another graph as if it were local (lesson 12).

CAPSTONE

Release Scout in production, and how this module stays true

Capstone brief (mock; the student project space is not built yet). Take Release Scout from lesson 2 to a deployed service:

  1. Rewrite the tool descriptions until your eval set (lesson 13) passes; add five questions of your own with answers you can check against PyPI.
  2. Put a human approval gate on any tool that writes or publishes (lesson 5), and prove the run survives a restart (lesson 8) with a Postgres checkpointer.
  3. Add a fact-checker subagent that answers only from verified facts and says "not verified" otherwise (lesson 10).
  4. Serve it with langgraph dev, call it from the SDK, then from another graph through RemoteGraph (lesson 12).
  5. Write one probe: a claim from an issue thread, the script that tests it, the dated environments it runs in, and your expected result written before you run it.

How this module stays current. The libraries ship every few days. Facts marked verified passed one of our probes and our verification gate; when a subject library releases, the knowledge base lists which probes are due, reruns them in a rebuilt environment, and flags any released lesson whose facts changed. During the build of this module deepagents 0.7.38 shipped, two probes became due, were rerun, and held.

What is not here yet. The LangGraph concept pages (graph API, persistence, durable execution) and the history sources marked general knowledge are not yet ingested into the knowledge base; their facts in this module come from the code that ran and from the instructor, and are labelled as such.
