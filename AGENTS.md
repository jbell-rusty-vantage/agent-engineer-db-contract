## Repository guide

Read the relevant documents below before changing behavior. Inspect more-specific AGENTS.md files in the destination directory. Accepted docs record settled decisions; proposed, reference, and deprecated docs are labelled context. The map is navigation, not proof of implementation or deployment.

- Start with `./dev status` (JSON orientation); before finishing run `./dev check` (typecheck, npm test, version:check, the agent-docs check, provenance). What each feature does and the command that proves it: [features/README.md](features/README.md); how a schema change moves today, input for the owner's schema session and not a rule: [features/schema-change.md](features/schema-change.md).

- Commit each ordered migration and regenerated src/database.generated.ts together. This repository is the only migration and type authority; consumers pin the contract.
- Schema batches follow the review workspace protocol: recommended, approved by John, then executed; no unapproved migration, version cut or grant change.
